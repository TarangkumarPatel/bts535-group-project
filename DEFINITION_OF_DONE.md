# Definition of Done:
**Definition of Done as the name says is a checklist or fix set of conditions that must be agreed upon by the entire team. Only the task adhering to this is considered as done.** 

**Project:** Privacy-First Local Agentic Knowledge Base and Code Synthesizer.

**Team:** Group 4

A user story is **Done** only when every item below is true.

## Requirements

- [ ] All acceptance criteria on the user story are met.
- [ ] All tasks (sub-issues) for the user story are completed and closed.
- [ ] The product owner or team agrees the story delivers the intended value.

## Code

- [ ] Code is written on a separate branch named after the issue.
- [ ] Code follows the team's style guidelines (PEP 8 for Python; ESLint and Prettier for TypeScript and React).
- [ ] Code has no obvious bugs, leftover debug output or commented-out blocks.
- [ ] No secrets, credentials or personal data are committed.
- [ ] The feature runs fully offline and sends no user data to any external service.

## Testing

- [ ] All testing criteria on the user story have been checked and pass.
- [ ] Unit tests are written for new logic where practical.
- [ ] All existing tests pass, both locally and in GitHub Actions CI.
- [ ] The feature has been manually tested in the running application.

## Review and Merge

- [ ] A pull request is opened that links the issue (`Closes #N`).
- [ ] At least one teammate has reviewed and approved the pull request.
- [ ] All review comments are resolved.
- [ ] The branch is up to date with `main` and has no merge conflicts.
- [ ] The pull request is merged into `main`. No direct commits are made to `main`.

## Documentation and Tracking

- [ ] The README or other documentation is updated if the feature changes setup, usage or architecture.
- [ ] The issue is closed and moved to the **Done** column on the project board.
